# Kriteia 仕様書 第6章 文法と構文

## この章の目的

Kriteia の字句規則、予約語、主要構文、構文上の優先順位を、第1版に必要な最小粒度で定義する。完全な grammar spec をいきなり凍結するのではなく、Kriteia の中心概念を書き表すために最低限必要な宣言構文と制御構文を先に固定する。特に `policy` の最小ブロック構文と、`accept` を文として扱う方針をここで明示する。

## この章で確定する事項

- 字句規則の最小骨子
- 予約語の最小集合
- 宣言構文と制御構文の大分類
- `claimset`、`prompt`、`policy`、`agent` の最小構文骨子
- `branch`、`checkpoint`、`judge`、`accept` の最小構文骨子
- 第1版で保留する曖昧性の主要論点

## 本文草案

### 6.1 文法定義の位置づけ

Kriteia の文法は、単にコードを解析するための記法一覧ではなく、探索、根拠付け、検証、受理というコア概念をどの単位で書けるかを定める仕様境界である。第1版では、完全な EBNF よりも、主要な宣言構文と制御構文が曖昧なく読めることを優先する。文法章の役割は、処理系内部の完全 grammar を先に固定することではなく、仕様本文の中心契約を安定させることにある。

### 6.2 字句規則の骨子

字句レベルでは、識別子、予約語、リテラル、区切り記号、型引数記法、ブロック境界を区別する必要がある。既存資料には完全な字句仕様はないが、第1版では `{}` によるブロック、`()` による引数列、`<>` による型引数、`:` による型注釈、`->` による出力型指定を最小中心記法として固定できれば十分である。細かい字句規則や例外処理は grammar spec 側へ送る。

### 6.3 宣言構文

第1版で主要宣言とみなすのは、`claimset`、`prompt`、`policy`、`agent` である。`claimset` は検証対象となる成果物の構造を、`prompt` は意味型付き生成契約を、`policy` は名前付きブロック内に `require` 条件を列挙する受理条件の束を、`agent` は探索から受理までの実行主体を表す。Kriteia の独自性を保つには、この 4 種の宣言を第一級として区別できればよく、さらに多くの宣言種別を第1版で増やす必要は薄い。

### 6.4 制御構文

制御構文としては、`branch`、`checkpoint`、`rollback`、`judge`、`accept`、`fallback` が中心になる。これらは一般的な命令型言語の `if` や `for` と同列ではなく、Kriteia の AI ライフサイクルを直接表す構文である。そのため、第1版でも単なる関数呼び出しへ潰さず、専用構文として扱う方針が妥当である。特に `accept` は `accept judged` のように JudgeResult または受理直前候補を引数に取る文として扱い、式としての値返却には使わない。ただし、各構文の細かな派生形まで正文で確定する必要はない。

### 6.5 優先順位と曖昧性

第1版で特に曖昧性が問題になるのは、型引数 `<...>` と比較演算子、`judge ... using ...` の連接規則、`branch` 本体と `fallback` の結び付きである。`accept` については、値を返す式ではなく最終段階を表す文として固定する。一次資料には例示はあるが完全規則はないため、本章では優先順位表の完全確定までは行わず、少なくとも「どこが未確定で、どこまでは読めるか」を示すに留める。完全な grammar spec は将来版候補として扱う。

## 構文カテゴリ案

- 宣言: `claimset`、`prompt`、`policy`、`agent`
- 実行段階: `explore`、`judge`、`accept`
- 探索制御: `branch`、`checkpoint`、`rollback`、`fallback`
- 型関連: 型注釈、型引数、accepted 型、draft 型

## 第1版で扱わないもの

- 完全な BNF / EBNF の正文固定
- すべての字句例外規則
- 構文糖や派生構文の網羅
- 高度な優先順位規則の最終確定

## 未決論点

- 完全な BNF と EBNF のどちらを正文とするか。
- `judge ... using ...` の連接順序を左結合で固定するか。
- `fallback` ブロック内で受理済み値をどう返すかを構文上どこまで固定するか。

## 決定メモ

- 第1版では主要宣言構文と制御構文の最小骨子を優先し、完全 grammar spec は将来版候補とする。
- `claimset`、`prompt`、`policy`、`agent` は第一級宣言として維持する。
- `policy` は名前付きブロックと `require` 条件列を持つ最小 DSL とする。
- `accept` は第1版では文として扱い、式としては許可しない。
