## 本文草案

### 8.1 探索の位置づけ

Kriteia における探索は、候補生成の補助手段ではなく、生成された候補を比較し、より妥当な枝を残すための正式な実行段階である。ただし第1版では、探索の一般理論を完成させることより、「候補は複数化できるが、そのまま受理されない」という最小契約を明確にすることを優先する。Kriteia に必要なのは探索能力そのものではなく、受理前に候補比較を組み込めることである。Explore の出力はあくまで draft 候補であり、04章でいう `grounded draft candidate` は Ground 段階を経た後に初めて成立する。

### 8.2 branch の役割

`branch` は複数 draft 候補を展開し、各枝に対して評価、制約確認、補助 retrieval を適用する構文である。これにより、Kriteia は単線的な生成ではなく、複数の可能性を比較しながら候補を育てる。第1版では、`branch` を「高度な探索 DSL」ではなく、「候補比較を明示する最小探索構文」として扱うのが簡素化方針に合う。ここで残った枝もまだ受理可能成果物ではなく、後続の Ground 段階で根拠接続を受けて `grounded draft candidate` になる前段階に留まる。

### 8.3 スコアリングと枝刈り

`width` は探索幅を、`score by` は候補評価関数を、`require` はその枝が満たすべき必須条件を表す。第1版では、dynamic width や複雑な score 型まで扱わず、少なくとも「条件不成立の枝は後続段階へ進めない」「スコアは枝選択の補助であり accept の代替ではない」「Ground を経て `grounded draft candidate` にならない限り Acceptance Gate の入力には入らない」という原則だけを正文に残すのが妥当である。高度な探索戦略は将来版送り候補として扱う。

### 8.4 checkpoint と rollback

探索途中で外部効果や高コスト処理を伴う場合、`checkpoint` と `rollback` により安全な地点へ戻れる必要がある。Kriteia では、探索の失敗や judge 不合格を例外的異常ではなく通常経路として扱うため、巻き戻しは探索制御の一部とみなされる。第1版では nested checkpoint の厳密意味論までは扱わず、`rollback` は復帰、`fallback` は代替経路、という最小差分を明示するに留める。

### 8.5 Choice Point Engine

Choice Point Engine は、各 branch の候補、スコア、制約違反、再探索地点を管理する概念的なランタイム要素である。第1版では、この名称を正文の中心に据えるより、「branch の結果がどのように比較され、どこで失敗枝が落ちるか」という観測可能な意味論を優先する。内部構成や最適化は参考記述または将来拡張へ回す。

## 探索における設計原則

- 探索結果はそのまま accepted にならない。
- Explore の出力は draft 候補であり、Ground 後に `grounded draft candidate` になる。
- スコアは候補比較の補助であり、受理判定の代替ではない。
- `require` 違反は枝レベルの失敗として扱う。
- `rollback` と `fallback` は同義ではない。
- 高度探索の詳細は第1版正文へ抱え込まない。

## 第1版で扱わないもの

- dynamic width の意味論
- 複雑な score 関数型
- 並列 branch の順序保証
- nested checkpoint の詳細規則

## 未決論点

- width を静的値として正文へ固定するか。
- `score by` の戻り値を単純な数値へ寄せるか。
- 並列 branch の順序保証を将来版送りで確定できるか。
- nested checkpoint の復帰範囲を第1版から外すか。

## 決定メモ

- 第1版では `branch` を最小探索構文として残し、高度探索の一般化は将来版候補とする。
- Choice Point Engine の詳細は正文より概念説明を優先する。
- Explore で残った候補は Ground を経るまで `grounded draft candidate` ではない。
